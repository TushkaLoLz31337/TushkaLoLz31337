# Contributing to Tushka

Tushka aims to strengthen decentralized, open-source communities through useful, inspectable, maintainable work. Contributions should increase shared capability.

## Before opening a pull request

1. Open an issue for substantial changes so the problem and scope can be discussed.
2. Keep the change focused and explain its intended impact.
3. Prefer open standards, portable formats, and interoperable interfaces.
4. Include tests or reproducible verification steps when applicable.
5. Document setup, limitations, security implications, and maintenance needs.

## Pull request checklist

- [ ] The change solves a clearly described problem.
- [ ] Scope is focused and backwards compatibility is considered.
- [ ] Tests or verification steps are included and results are accurately reported.
- [ ] Documentation is updated.
- [ ] No credentials, private data, or unlicensed third-party material are included.
- [ ] Dependencies and security implications are explained where relevant.

## Discussion standard

Be direct, curious, and evidence-led. Challenge ideas without attacking people. Explain trade-offs. A respectful disagreement with a reproducible argument is valuable.

## Project status

This profile repository is currently a public identity and contribution entry point, not a mature software product. Do not assume that a feature, service, or support commitment exists unless it is documented in the relevant project repository.
